# Warehouse Keeper Voice 使用说明

## 一、概述

Warehouse Keeper Voice（下称「本附加包」）是 Minecraft 模组
[Warehouse Keeper](https://github.com/2567922141/warehouse-keeper) 的可选语音取货附加包。

主体模组以可视面板与指令提供仓库查询、取货与搬运工作业；本附加包在此基础上增加一种输入方式：
玩家按住按键说出取货需求，本附加包在本机完成语音识别，将其解析为一条标准的
`/warehouse order <物品> <数量>` 取货指令，其余流程（权限校验、库存校验、搬运工派送）与玩家在
面板中点击取货完全一致。

本附加包为纯客户端模组，服务器无需安装，未安装本附加包时主体模组的行为不受任何影响。

## 二、工作原理

1. **采集**：按住按键期间，通过 OpenAL Soft（游戏自带）采集麦克风音频，采样率 48 kHz、单声道 16 位；
   采集失败时回退到 Java Sound。松开按键结束采集。
2. **预处理**：先做一阶高通滤波（约 70 Hz，滤掉桌面共振、空调轰鸣这类低频噪声），按 20 ms 一帧
   估算噪声底与人声电平，再用**人声段的均方根**（而不是整段的最大电平）归一化音量，并单独判断
   信噪比 —— 贴着麦克风说和隔着两米说，喂给模型的电平基本一致；若整段能量太低，会直接拒绝识别
   而不硬猜。拒绝时会说明原因：如果低频（200 Hz 以下）占了绝大部分能量，提示的是「低频轰鸣/交流声
   太强，是噪声盖住了人声」；否则才提示「人声太轻或太远」。识别结束后，内存中的音频缓冲区立即清零。
3. **识别**：由 sherpa-onnx 在本机 CPU 上运行中文语音识别模型（默认 SenseVoice，对多口音与远场
   更稳）。**语音包不内置任何模型**，四个模型（SenseVoice / Paraformer 小 / Zipformer-CTC /
   Paraformer 完整版）都要在设置页里按需下载；可在设置页里用主、副两个模型并行识别，
   两条结果均参与后续匹配。
4. **匹配**：在仓库实际持有的物品范围内进行闭集匹配，综合字形相似度与拼音相似度
   （含同音与近似音判定）给出候选；主模型未能识别物品名时，另一模型的结果自动接续。
   匹配成功的说法（含纠正成功的说法）会写入本机别名表，供后续直接命中。
5. **下单**：通过校验后发送一条普通的取货指令。未识别到物品、无取货权限、未收到仓库数据、
   数量超出上限或库存不足时，一律不下单并给出中文说明。

## 三、环境要求

| 组件 | 版本要求 |
| --- | --- |
| Minecraft | 26.3 |
| Fabric Loader | 0.19.3 或更高（实测 0.19.5） |
| Fabric API | 0.161.0+26.3（或兼容版本） |
| Java | 25 或更高 |
| 主体模组 | warehouse-keeper 1.1.4 或更高 |
| 操作系统 | Windows x64（当前版本仅随包提供 Windows 原生库） |

## 四、安装

1. 安装主体模组 `warehouse-keeper`：服务端与客户端均需安装。
2. 将 `warehouse-keeper-voice-<版本>.jar` 放入客户端 `mods/` 目录。
3. 启动游戏。首次使用时，随包附带的原生库（约 8 MB）会解压至 `config/warehouse-keeper-voice/`，
   该解压过程仅执行一次。
   **语音模型不随包分发**：输入 `/warehousevoice` 打开设置页，在想要的模型那一行点「下载」
   （SenseVoice 约 228 MB、Paraformer 小约 78 MB、Zipformer-CTC 约 350 MB、Paraformer 完整版约 217 MB），
   下载完成后即可识别；一个模型都没下载时，按住 `V` 会提示「先去设置页下载一个」。
   想省 CPU 与内存就下 Paraformer 小，想认得更准就下 SenseVoice（默认）。
4. 语音下单沿用主体模组的取货权限，需由管理员在仓库面板「权限」页授予该玩家取货权限。

## 五、使用

| 按键 / 指令 | 功能 |
| --- | --- |
| `V`（按住） | 按住说话，松开后立即识别 |
| `/warehousevoice` | 打开语音设置页：选主模型、选副模型、下载/删除模型、换下载源、开关对照/并行/预加载 |
| `/warehousevoice status` | 在聊天栏打印当前语音配置（`/wvoice` 同义） |

聊天栏是否多显示另一个模型那一行，由 `config/warehouse-keeper-voice/settings.txt` 的 `compare=`
控制；本附加包不占用其他快捷键（主体模组默认用 `B` 打开仓库面板）。

设置页里改过的选项在点「保存并应用」后写入 `settings.txt` 并立即生效；下载在后台进行，
进度直接显示在设置页里，关掉设置页也不会中断。

识别结果与下单结果会显示在动作栏与本地聊天栏中。示例说法：

- 「给我十二个红色染色玻璃」
- 「拿一组圆石」
- 「半组圆石」（= 半堆，一组 64 个时取 32 个）
- 「三组半」「全都给我」「剩下的都要」「来点闪长岩」「一半」

数量说法支持：`N个`、`N组`、`半组`、`N组半`、`全部 / 都 / 所有 / 剩下的都要`、`一半`、`半组`、
`半个`、`来点 / 一些 / 一点儿 / 若干`；回显会写明按哪个说法算的（例：「（按「半组」算，一组 64 个）」）。
装了主体模组 **1.2.1** 或更高时，仓库面板「设置 → 语音取货」页也能看到同一份设置：模型下载 / 取消 /
删除（删除要点两下）、下载进度、AI 归一化开关与用量。页面按功能**分区**（识别模型 / 识别方式 / 模型下载 / AI 功能；AI 页再分 服务凭据 / 连通性 / 用量），主模型、副模型、下载源、AI 服务是**下拉菜单**，AI 页还有「**测试连通性**」按钮（点一下给出结果与延迟，不占额度）。

仓库里有同名不同料的物品时（迟缓药水 / 喷溅型迟缓药水、各种附魔书……），可以连**具体那一种**一起说：

- 「迟缓药水」「半组迟缓药水」（一组 1 个，所以半组也是 1 个）
- 「喷溅型迟缓药水」「来半组喷溅型迟缓药水」
- 「附魔书」（落在其中一种变体上；要精确就说名字，或在面板物品页点那一行取货）

变体名字来自物品的真实名字（中文客户端就是中文），专用服务器的英文名字不影响取货：

### 一句话要好几件东西

「给我一本背刺附魔书和一张绿色床」这种一句话要两件的，会分别下成两条取货单：先由**本地**按
「和 / 还有 / 以及 / 、 / ，」等连接词拆句，每件单独认（数量词、别名、变体都照旧），全对得上就
直接逐件下单、**不问 AI**。只有本地有认不出的那件时才问一次 AI，AI 按件回行（最多 4 件），每行
仍要过本地复判；补齐时本地已经认出的那几件不会丢，两边的件按 id 合并后一起下单。超过 4 件会提示「一句话最多一次说 4 件东西，请分开说（这次没有下单）」；一件都
没听出时会提示用「和／还有」把每件说清楚。同一句里说到同一物品的两次会先合并数量。

### 名字相近但不是一个东西（不会张冠李戴）

仓库里只有「橡木木板」时你说「橡木原木」，以前会被当成同一件直接下单；现在只回一句
「仓库里没有「橡木原木」——最接近的是：橡木木板；名字确认后再说一遍」，**不拿相近的顶替**。
别名表命中（你以前确认过的说法）不受影响；同音近音（「身板盐」→ 深板岩）仍按上面的同音纠错处理。
开了 AI 归一化时，这种「名字只是相近」的句子会交给 AI 复判一次，但模型点名的物品必须在你原话里
找得到同源说法，否则一样不下单。

### 三种用法：完全本地 / 两个一起 / 完全 AI

设置页（面板「设置 → 语音取货 → AI 归一化」或 `/warehousevoice`）里的「**方式**」按钮，点一下换一档：

| 档位 | 行为 |
| --- | --- |
| 完全使用本地规则 | 一个字节都不出网；Key 与服务配置保留，随时可切回来 |
| 两个一起（本地优先） | 默认；本地先认，本地没把握才问一次 AI，AI 契约仍要本地复判 |
| 完全调用 AI 改写 | 每句都先问一次 AI；AI 给合法契约就优先采用；超时 / 没 Key / 契约不合法时退回本地并提示 |

对应 `settings.txt` 的 `rewrite.mode=both|local|ai`（中文别名「两个一起 / 本地 / 只用AI」也认）。


### 报错说清原因、带属性的物品能选对

- 仓库里确实**没有**这件东西时，提示是「没找到「橡木原木」——仓库里可能没有这件东西，也可能名字没听准；最接近的是：…」；只有连物品短语都没听出来时才说「没听出物品名」。一句话要好几件时，会逐件说清哪件没对上。
- 药水的时长/强化等级、附魔等级、烟花飞行时长这类「同一物品多个属性行」，开 AI 归一化后模型按候选表里的编号回答（`item=#1`、`item=#3`…），并照抄整段变体 id；基础 id 对应多行时一律作废，不会瞎猜。本地复判也不再因为「药水：迟缓 IV 0:20」这类注解把正确变体拒掉。

### AI 归一化（可选，默认关）

本地匹配**没听出物品名**时，可以再问一次小模型：把「识别出的那句话 + 本地前 8 名候选（物品 id、
中文名、库存）」发出去，让模型按件回行（每行 `item=…; amount=…; rewrite=…`，一句话最多 4 件），
然后**由本地匹配器逐行复判** —— 只有本地也认了才下单。所以模型出错最多是「没帮上忙」，不会取错物品。

| 项目 | 行为 |
| --- | --- |
| 触发条件 | 本地没把握（没听出物品名，或名字只是相近、不像同一件东西；多件句里有个别件拿不准）、且开关是开着的；一次识别最多问一次，失败不重试；本地已经听懂时一个请求都不发 |
| --- | --- |
| 只发送 | 识别文字 + 本地前 8 名候选（id、中文名、库存数） |
| 不发送 | 音频、玩家名 / UUID、坐标、仓库坐标、整份仓库清单、聊天记录 |
| 限额 | 20 次/分、200 次/天；同一句第二次不再联网（缓存 + 别名沉淀） |
| 超时 | 默认 1000 ms（可配 500–3000）；调用在后台识别线程里，不卡游戏 |
| 出错 | 超时 / 断网 → 退回本地提示；Key 无效（401）→ 提示一次并**自动关闭开关**；被限速（429）→ 60 秒内不再调用；输出不合契约 → 当没答 |

四个预设：**智谱 BigModel**（默认）、**硅基流动**、**本地 Ollama**（完全离线、不用 Key）、**自定义**。
Key 在 `/warehousevoice` 的「AI 归一化」分区里填（单独界面，回显只显示前 4 位）；配主体 1.2.1 时也可以直接在面板「设置 → 语音取货 → AI 归一化」页的那一行里粘贴（真输入框，按回车或离开这一页即保存）。另可在
`settings.txt` 里手改 `rewrite.key=`。

## 六、配置

配置文件位于 `config/warehouse-keeper-voice/settings.txt`，修改后需重新进入游戏生效：

| 配置项 | 取值 | 说明 |
| --- | --- | --- |
| `primary` | `sense-voice` / `paraformer-small` / `zipformer-ctc` / `paraformer-zh` | 优先采用哪个模型的识别结果（默认 `sense-voice`；没下载时自动回退到已装的模型并在聊天栏说明） |
| `secondary` | 同上，或 `off` | 主模型没听懂时顶上的副模型；`off` 表示只跑主模型 |
| `compare` | `on` / `off` | 聊天栏是否显示另一模型的结果（不影响两个模型同时运行） |
| `parallel` | `on` / `off` | 两个模型是否并行识别（关闭后更省内存，但用时更长） |
| `preload` | `on` / `off` | 启动后是否在后台预先装载模型 |
| `mirrorMode` | `official` / `hfm` / `modelscope` / `auto` / `custom` | 下载源（默认 `official`，即官方原始源 `huggingface.co`）；设置页里点一下就在这五个之间轮换 |
| `mirror` | 网址前缀 | 只在 `mirrorMode=custom` 时作为自定义前缀使用；同时为老版本保留一个它能用的地址 |

下载源的五个选项：

| 选项 | 界面名 | 说明 |
| --- | --- | --- |
| `official` | HuggingFace 官方 | 默认。原始下载源，需要能连上 `huggingface.co` |
| `hfm` | hf-mirror | 国内可达的转发站。实测会 308 跳回官方，**不是**独立的一份源 |
| `modelscope` | 魔搭 ModelScope | 大陆直连。四个模型都已实测收录，没有收录的模型自动回退官方 |
| `auto` | 自动 | 按顺序试：魔搭（有镜像时）→ hf-mirror → 官方 |
| `custom` | 自定义前缀 | 手填网址前缀，按「前缀/repo/resolve/main/文件名」拼 |

任一源失败都会自动换下一个（已下载的 `.part` 保留，续传继续），全部失败才报错并说明最后试的是哪个源。
老配置兼容：设置文件里只有 `mirror=` 而没有 `mirrorMode=` 时，按地址反推模式 ——
`https://hf-mirror.com` 认成 hf-mirror，`https://huggingface.co` 认成官方，其它网址认成自定义前缀
（与旧版本「非空 `mirror` 当前缀拼」的行为一致）；`mirrorMode=` 的值认不出来时记一条日志并回到默认官方。

老写法仍然认：`primary=paraformer` 等价于 `paraformer-small`，`zipformer` 等价于 `zipformer-ctc`。

AI 归一化相关（默认关，第 ② 步）：

| 配置项 | 取值 | 说明 |
| --- | --- | --- |
| `rewrite.mode` | `both` / `local` / `ai` | 三种用法：`both` 两个一起（本地优先，默认）/ `local` 完全本地（不联网）/ `ai` 完全调用 AI 改写（每句都先问一次，AI 契约优先、本地复判兜底）；中文别名「两个一起 / 本地 / 只用AI」也认 |
| `rewrite` | `on` / `off` | 是否启用 AI 归一化（**默认 `off`**）；关着时一个字节都不出网 |
| `rewrite.preset` | `zhipu` / `siliconflow` / `ollama` / `custom` | 服务商预设（默认 `zhipu` 智谱 BigModel）；`ollama` 是本地服务，不用 Key |
| `rewrite.url` | 网址前缀 | 接口地址；留空时按预设。预设之外的组合只能手改本文件 |
| `rewrite.model` | 模型名 | 留空时按预设（智谱 `glm-4.7-flash`、硅基流动 `Qwen/Qwen3-8B`、本地 `qwen3:0.6b`） |
| `rewrite.key` | API Key | **明文**保存在本文件里；界面上只显示前 4 位。不要把这个文件发给别人 |
| `rewrite.timeout` | 500–3000 | 单次调用超时毫秒（默认 `1000`） |

别名表位于 `config/warehouse-keeper-voice/aliases.txt`，每行格式为 `听到的说法=物品id`，
例如：

```
鞍山人=minecraft:andesite
```

手工修改与自动记录的内容同存于此文件，最多 200 行。自动记录的**键只含物品名、不含数量**
（「十个金币」记成 `金币`），于是「五个金币」这样的说法同样命中；只有一两个字的退化说法
（例如恰好归一化成「给」「给我」）不再写入别名表，旧版本留下的这类条目会在加载时自动剔除，
原文备份为同目录下的 `aliases.txt.bak`。

## 七、数据与隐私

- 语音识别完全在本机完成；识别过程中不进行任何网络通信。
- 联网只发生在两种情况：① **你在设置页里主动点「下载模型」**（从你所选的下载源下载模型文件，
  默认官方 `huggingface.co`，可选魔搭 ModelScope / hf-mirror）；② **你自己打开了「AI 归一化」
  开关**之后，本地没听出物品名时会向该开关指定的服务商发一次请求。这两种情况之外，本附加包不会
  发起任何网络请求；**AI 归一化默认关闭**，不开开关就一个字节都不出网。
- 开启 AI 归一化后**发送的内容**：语音识别出的文字 + 本地打分前 8 名候选（物品 id、中文名、
  库存数）。**不发送**：音频、玩家名 / UUID、坐标、仓库坐标、整份仓库清单、聊天记录。
- API Key **以明文**保存在本机 `config/warehouse-keeper-voice/settings.txt`（和 `primary`、
  `mirror` 同一份文件，方便手改）；该文件不在存档里、不进 git。**请不要把这个文件发给别人。**
  想完全不联网可用「本地 Ollama」预设（不需要 Key）。
- 第三方服务商的条款各不相同（有的免费层明确会把内容用于改进产品），使用前请自行确认。
- 录音数据仅以内存缓冲区形式存在，识别结束后立即清零，不写入磁盘。
- 识别文本仅显示于本机动作栏与聊天栏，不发送至服务器或其他玩家。
- 运行时写入磁盘的内容仅限 `config/warehouse-keeper-voice/` 下的模型、设置与别名文件，
  绝不写入任何世界存档目录。

## 八、常见问题

**麦克风没有声音**
请确认 Windows 的「设置 → 隐私和安全性 → 麦克风」中已打开「麦克风访问」与
「允许桌面应用访问麦克风」，并确认麦克风未被其他程序独占。

**识别结果与说法不一致**
可在聊天栏查看识别文本；系统会给出最接近的候选名称，按候选名称再说一次即可，
该说法随后会被记入别名表。亦可直接编辑 `aliases.txt`。

**同一个人说得很准，别人说就不准**
旧版本按「整段最大电平」放大录音，只有音量本来就够大的人（例如贴着麦克风说话的人）
才刚好被放大到合适电平，说得轻、离得远的人则被喂进很小的声音，模型难以识别。
现在改为高通滤波 + 按人声段均方根归一化 + 信噪比判断，不同音量与距离下喂给模型的电平一致；
如果识别仍不稳定，可到设置页把主模型换成 SenseVoice（对多口音更稳），或让对方把麦克风
靠近一些。

**模型下载失败 / 很慢**
先看设置页里「下载源」当前是哪一项：

- 默认是 **HuggingFace 官方**（`huggingface.co`），国内直连常常很慢甚至连不上。
- 大陆网络建议切到 **魔搭 ModelScope**：直连可用，四个模型都已实测收录（与官方逐字节同一份），
  仓库文件列表里的大小与 sha256 与官方写死的值完全一致（2026-10-16 复核）。
- **hf-mirror.com** 只是把请求转发到 `huggingface.co`（实测两者最终落到同一个 CDN），
  **不是**一份独立可用的备份源 —— 连不上 huggingface 时换它也一样下不动。
- 不想自己挑就选 **自动**：按「魔搭（有镜像时）→ hf-mirror → 官方」的顺序试，前一个不通自动换下一个。

某一个源失败会自动换下一个源继续，不需要你手动重来；下载支持断点续传，已下载部分保存在 `.part`
文件里，中途关游戏不会白下；下载完成后会校验确切字节数与 sha256，校验不通过会重新下载。
下载日志里会写出「下载源：…」与「候选下载源（按顺序试）：…」，进度条后面也会标出当前正在用的源。

**被提示「低频轰鸣/交流声太强」，但我说话声音不小**
这条提示不是在让你喊大声，而是环境里的低频噪声（风扇、音响、变压器、电源线、地环路）盖住了人声：
一阶高通滤波（约 70 Hz）对 50/60 Hz 交流声只能衰减约 1.3 dB。按提示离这些设备远一点，或在 Windows
声音设置里关掉麦克风的「增强／自动增益」再试。它与「人声太轻或太远」是两种不同的判定：前者说明
200 Hz 以下的低频占了这段录音绝大部分能量（实测被误拒的低频轰鸣占比 0.735~0.978，正常录音在
0.17~0.66），后者说明音量确实不够。

**内存占用偏高**
每个模型常驻内存约 0.3–1 GB（SenseVoice 最大）。可在 `settings.txt` 中设置 `parallel=off`
或 `preload=off` 以降低占用，也可把主模型换成 `paraformer-small`。

**下单被拒绝**
请检查：是否有取货权限、是否至少打开过一次仓库面板（以获取仓库数据）、
仓库中是否存在该物品且数量充足。
