# Warehouse Keeper Voice v0.3.0

本版两件事：① **不再内置任何语音模型** —— 四个模型全部改成在设置页里按需下载，包体从约 79 MB 降到 **约 8 MB**；② 修掉 0.2.0 里「输入 `/warehousevoice` 后设置页闪一下就消失」的问题，并顺手收掉一批识别前处理与设置页的小毛病（失败日志度量、越界崩溃、主模型指向未下载模型时的提示、同一段录音被处理两三遍、两个阈值共用一个常量）。

## ✨ 本次变更

- **不再内置语音模型，包体由约 79 MB 降到约 8 MB**：jar 里只剩下 sherpa-onnx 的 Java 绑定与 Windows x64 原生库（`onnxruntime.dll` + `sherpa-onnx-jni.dll`），**不含任何模型文件**。SenseVoice（约 228 MB，默认）、Paraformer 小（约 78 MB）、Zipformer-CTC（约 350 MB）、Paraformer 完整版（约 217 MB）都在语音设置页里自己选、自己下，只为自己要用的那个花流量与磁盘。
- **第一次使用必须先下载一个模型**：一个模型都没有时按住 `V` 会明确提示「还没有可用的语音模型：输入 /warehousevoice 打开语音设置页，先下载一个」，而不是静默失败或含糊其辞。
- **老用户不用重下**：0.2.1 及更早版本解压出来的 `config\warehouse-keeper-voice\sherpa-paraformer-zh-small\` 仍被认作「已装」（识别会直接用它），不会因为这次「取消内置」而白重下一遍。
- **「删除」按钮现在也管老目录那一份**：以前它只删自己下载的目录、刻意不动老目录；现在点删除会把当前在用那一份删掉（删老目录时日志里注明「老版本解压出来的那一份」），要再用重新下载即可。

## 🐛 问题修复

- **设置页「闪一下就消失」（本版唯一改动）**：0.2.0 是在客户端命令的回调里**同步**打开设置页的。而 26.3 的聊天界面按回车时是「**先执行命令，再关掉聊天界面**」——把 26.3 客户端 `ChatScreen.keyPressed` 反编译出来看得很清楚：先 `handleChatInput(...)`（命令在这里跑），紧接着在 `closeOnSubmit` 为真时 `Gui.setScreen(null)`。于是我们刚设好的设置页被紧接着的关闭动作覆盖掉，表现就是「界面闪一下又回到游戏」（游戏本身没有崩溃：那次会话的 `exitCode = 0`、`crashed = false`、没有 crash 报告，日志里也没有任何异常栈）。
  现在改成：命令只**登记**「要打开设置页」，真正的打开推迟到下一个客户端 tick（那时聊天界面已经关完了），并且不再把「正在关闭的聊天界面」记成上一页 —— 关掉设置页会正常回到游戏。
  `/warehousevoice status` 不受影响（它只在聊天栏打一行字）。

- **录音被拒时日志里的电平数字恒为 0**：失败分支以前统一塞 `Audio(0,0,0,0)`，把**已经算好**的峰值／人声 RMS／噪声底全丢了 —— 玩家说「我明明说话了却被判太轻」时，日志里看不到当时到底是什么电平，等于没有排查线索。现在失败也带上真实度量（`SherpaEngine.failed(...)` 重载），并把这一行补进 `VoiceSession` 的日志。

- **`transcribe(byte[], int)` 不校验长度，越界直接崩客户端**：公开入口以前直接用调用方给的 `length`（`sampleAt` 会读 `pcm[2i+1]`），越界抛 `ArrayIndexOutOfBoundsException`，而调用方没接住 ⇒ 客户端崩溃。现在入口先夹取 `length = min(length, pcm.length)` 并对 `pcm == null` 给出「没有录到音频数据」。

- **同一段录音被处理两三遍**：「松开按键」时体检一次（高通 + 分帧 + 裁剪 + 增益），真正识别时又整段算第二遍（`analyze` → `prepare` → `transcribe`）。纯函数跑两遍现在看着结果一致，但白烧 CPU，将来改了一处就是隐性 bug。现在体检结果（`Prepared`）直接交给识别线程复用，**只处理一遍**。

- **两个阈值共用一个常量**：拒绝门槛与「掐头去尾」门限以前都是 `SNR_MIN = 2.0`，想让裁剪更狠就会顺带把正常说话判成「没声音」。现在拆成独立的 `SNR_REJECT` 与 `SNR_TRIM`，可以单独调。

- **主模型可以指到没下载的模型却不说明后果**：设置页选了未下载的模型只回一句「已改成 X」，之后每次识别都悄悄回退到已装模型。现在当场说明「先点右边『下载』，下载完成前识别会自动改用已装的模型」。

## ⚠️ 已知局限

同 0.2.0（本版未动识别逻辑）：

- 环境里有**很响的 50/60 Hz 交流声／地环路嗡鸣**时，说话可能被误报「人声太轻或太远」：一阶高通在 60 Hz 只衰减约 1.3 dB，噪声底被抬高后信噪比可能压到 2 倍以下。真修需要更高阶的高通或频谱分离，本版未做；遇到时换一副麦克风或关掉增益增强即可。
- Paraformer 小模型（按需下载的那一份）对**口音、方言、轻声**的能力弱于 SenseVoice，长期使用建议下载 SenseVoice。
- 只有 transducer 类模型支持「热词表」，Paraformer／Zipformer-CTC 都不支持，所以这块没有做。
- 下载器带断点续传（`.part` + `Range` + `Content-Range` 校验 + 416 重来）。**2026-10-16 实测**（JDK `HttpClient`、跟随重定向、请求 `Range: bytes=…`）：`hf-mirror.com` 与 `huggingface.co` 都会 30x 跳到同一个 CDN（`us.aws.cdn.hf.co`），续传**确实生效** —— `bytes=0-99` 与 `bytes=1000000-1000099` 都返回 `206` 且 `Content-Range` 正确，起点越界返回 `416`。要注意的是：这条「镜像」并不是独立的一份源（它只是转发到 huggingface），所以连不上 huggingface 时换镜像也没用。

## ⬆️ 升级提示

- 把 `mods\` 里的旧 `warehouse-keeper-voice-*.jar` 换成 `warehouse-keeper-voice-0.3.0.jar` 即可（不要同时留两个同名模组 ID 的 jar）。
- **版本号定为 0.3.0**：这次的「不再内置模型」与删除语义变化是可见行为变更，所以没有沿用此前未发布的 `0.2.1`，直接记为 `0.3.0`（两者功能完全相同，只是版本串不同）。
- **升级后第一次进游戏记得下载模型**：如果 `config\warehouse-keeper-voice\models\` 下还没有任何模型、老目录 `sherpa-paraformer-zh-small\` 也不存在，按住 `V` 会提示先去设置页下载一个。老版本已经解压出来的那份仍算「已装」，不用重下。
- `config\warehouse-keeper-voice\` 下的设置、别名表与已下载的模型原样沿用；主体模组仍需 1.1.4 或更高，服务端无需安装本附加包。
